Custo de Queries e a Importância da Otimização

CustoQuery — Conceito

O que é Custo de Query?

Custo é a estimativa do PostgreSQL do quanto de recursos — CPU, I/O, memória e tempo — será necessário para executar uma consulta. Não é o tempo real: é uma medida interna do planejador para comparar planos alternativos e escolher o mais eficiente.
💡
O custo não tem unidade física. Um custo de 1000.00 não significa "1000 milissegundos" — é uma estimativa relativa usada internamente. Dois planos com custo 500 e 5000 nos dizem que o primeiro é estimado como 10× mais eficiente.

Papel do Desenvolvedor / DBA

👩‍💻

O Desenvolvedor ou DBA é quem:

  • Escreve a consulta SQL
  • Interpreta o plano de execução com EXPLAIN
  • Identifica gargalos de performance
  • Aplica as otimizações (índices, reescrita, manutenção)

As 4 Métricas de Custo

⏱

Tempo de Execução

Quanto tempo o banco leva para retornar o resultado.

💾

Uso de I/O

Quantas páginas de disco são lidas.
seq_page_cost · random_page_cost

⚙️

Uso de CPU

Custo de processar cada linha.
cpu_tuple_cost · cpu_operator_cost

🧠

Uso de Memória

RAM necessária para sorts e hashes.
work_mem

Por que isso importa?

Uma query com custo alto significa que o PostgreSQL está trabalhando muito para responder. Isso impacta diretamente a performance da aplicação, a experiência do usuário e o custo de infraestrutura.

🐌 Query sem otimização

Seq Scan em 500k linhas: ~200ms por requisição. Com 1.000 req/min → 3,3 min de CPU/min despendidos só nessa query.

⚡ Query otimizada

Index Scan com índice adequado: ~0,1ms por requisição. Redução de 2000× no tempo — mesma infraestrutura, muito mais capacidade.

-- Query lenta: busca sem índice em 500.000 linhas
SELECT * FROM pedidos WHERE cliente_id = 42;

-- Diagnóstico com EXPLAIN ANALYZE
EXPLAIN ANALYZE SELECT * FROM pedidos WHERE cliente_id = 42;

-- Saída esperada (Seq Scan):
-- Seq Scan on pedidos  (cost=0.00..12543.00 rows=47 width=52)
--                      (actual time=0.089..198.432 rows=47 loops=1)
-- Planning Time: 0.8 ms  |  Execution Time: 198.5 ms

-- Criar o índice:
CREATE INDEX idx_pedidos_cliente ON pedidos(cliente_id);

-- Após o índice — Index Scan:
-- Index Scan  (cost=0.42..1.85 rows=10 width=52)
--             (actual time=0.032..0.041 rows=10 loops=1)
-- Execution Time: 0.12 ms
